# Пайплайн подготовки белковых рецепторов для докинга

Полуавтоматический пайплайн: из кристаллической/крио-ЭМ структуры (`.pdb`/`.cif`)
и бокса докинга готовит рецептор `.pdbqt` для AutoDock Vina. Заточен под
**off-target панель** (докинг тест-лигандов в контрольные белки для проверки
селективности), но подходит для любой докинг-подготовки.

Главная идея: **бокс докинга — источник истины о расположении кармана**. Всё,
что близко к боксу, готовится тщательно; всё, что далеко, обрабатывается грубо
(не влияет на докинг).

## Быстрый старт

```bash
# 0. Проверить окружение (см. раздел про PATH!)
python check_setup.py

# 1. Одна структура (интерактивно — будут вопросы на checkpoint'ах):
python prepare_receptor.py -i 2vt4.cif -c box_config -o out/

# 2. Много структур (без вопросов, авто-режим):
python batch_run.py --root /путь/к/папкам --script ./prepare_receptor.py \
    --out run_results --fallback openbabel

# 3. Проверка качества (редокинг нативного лиганда):
python validate_redock.py --results run_results --root /путь/к/папкам \
    --out redock_results --targets 2vt4 3kk6
```

## Установка окружения

Пайплайн зависит от нескольких химинформатических пакетов. Самый простой путь —
conda-окружение из приложенного файла:

```bash
conda env create -f environment.yml
conda activate receptor_prep
python check_setup.py        # ОБЯЗАТЕЛЬНО проверьте, что всё встало
```

### Зависимости и зачем они

| Пакет | Зачем | Критичность |
|-------|-------|-------------|
| `gemmi` | чтение `.pdb`/`.cif`, геометрия, расстояния до бокса | обязательно |
| `meeko` (`mk_prepare_receptor.py`, `mk_prepare_ligand.py`) | основная сборка рецептора и лиганда в `.pdbqt` | обязательно |
| `pdbfixer` + `openmm` | достройка боковых цепей близких остатков (Стадия 2.5) | обязательно |
| `openbabel` (`obabel`) | запасная сборка, когда Meeko не справляется | обязательно |
| `propka` | предсказание pKa для His-таутомеризации близких к боксу гистидинов | обязательно |
| `rdkit` | расчёт RMSD в редокинг-валидации | для validate_redock |
| `AutoDock Vina` (`vina`) | редокинг нативного лиганда | для validate_redock |

### Запасной путь (если conda-пакет не встал)

Часть пакетов на отдельных платформах проще ставить через pip внутри
активированного окружения:

```bash
pip install meeko propka pdb2pqr
# pdbfixer/openmm — если не из conda:
conda install -c conda-forge pdbfixer openmm
```

**AutoDock Vina — отдельная тонкость.** `pip install vina` даёт Python-биндинги,
но **не всегда** даёт CLI-команду `vina`. Если `check_setup.py` пишет, что
`vina` не найдена, скачайте бинарник со страницы релизов AutoDock Vina и
положите его в PATH. Vina нужна **только** для `validate_redock.py`; для самой
подготовки рецепторов она не требуется.

## Ловушка PATH

**Это самая частая причина «непонятных» ошибок. Прочитайте обязательно.**

На многих системах `python3` и `python` указывают на **разные** интерпретаторы.
Например, `python3` может вести на системный Python без `gemmi`/`meeko`, а
нужное окружение доступно как `python`. Если запустить пайплайн «не тем»
питоном, вы получите `ModuleNotFoundError: gemmi` или `mk_prepare_receptor.py
не найдена`, хотя всё «установлено».

**Правило:** запускайте пайплайн **тем самым** интерпретатором, при котором
`check_setup.py` проходит без ошибок. Проверить, какой это python:

```bash
python check_setup.py        # смотрите строку «Интерпретатор: ...»
python3 check_setup.py       # сравните — возможно, это РАЗНЫЕ окружения
```

Если у вас conda-окружение `receptor_prep`, после `conda activate receptor_prep`
обычно правильным будет просто `python`. В batch-скриптах можно явно указать
интерпретатор флагом `--python /полный/путь/к/python`.

## Сценарий 1: одна структура

Интерактивный режим — пайплайн задаёт вопросы на ключевых развилках (checkpoint).

```bash
python prepare_receptor.py -i СТРУКТУРА.cif -c БОКС -o ВЫХОДНАЯ_ПАПКА/ [-l КОД_ЛИГАНДА]
```

Аргументы:
- `-i` — входная структура (`.pdb` или `.cif`).
- `-c` — файл бокса в формате Vina (`center_x/y/z`, `size_x/y/z`).
- `-o` — папка для результатов.
- `-l` — (необязательно) HET-код целевого лиганда. Если не указан — можно
  включить авто-детект (`--auto-ligand`).

Пример:

```bash
python prepare_receptor.py -i 2vt4.cif -c box_config -o out/ -l P32
```

### Какие вопросы задаст пайплайн (checkpoint'ы)

1. **Неизвестный гетероатом.** Если встретился HET-код не из словарей, спросит,
   к чему его отнести: `cofactor` / `buffer` / `ligand` / `ion` / `keep`. По
   умолчанию (Enter) в неинтерактиве — `buffer` (удалить). Подумайте: это
   функциональная молекула (вернуть как кофактор) или кристаллизационный мусор
   (buffer)?

2. **Возврат кофактора/иона к боксу.** Если близко к боксу есть кофактор (NADP,
   FAD, ион металла), спросит, вернуть ли его в рецептор. **По умолчанию — нет.**
   Возвращайте, только если уверены, что кофактор формирует карман. Случайный
   детергент рядом с боксом возвращать НЕ нужно — он испортит карман.

3. **Сборка при неудаче Meeko.** Если Meeko не смог собрать, спросит — собрать
   через OpenBabel (обходной путь) или прервать; если виноват кофактор — выкинуть
   его и пересобрать. Подробности в разделе [классы проблем](#классы-проблем).

### Формат файла бокса

```
center_x = 18.16
center_y = 24.43
center_z = -13.48
size_x = 22.48
size_y = 16.18
size_z = 20.32
```

Это стандартный конфиг Vina. Имя файла — любое (`box_config`, `box_config.txt`,
`vina_box.conf`).

## Сценарий 2: много структур (batch)

Для пакетной обработки папок (в каждой подпапке — один `.cif`/`.pdb` и
`box_config`). Два этапа: сначала **триаж** (разведка), потом **полный прогон**.

### Этап А — триаж (разведка, без сборки)

Быстро проходит все структуры до Стадии 2 (анализ + классификация + диагностика),
**без вопросов**, и собирает картину: где чисто, где проблемные остатки, какие
неизвестные HET-коды встретились.

```bash
python batch_triage.py \
    --root /путь/к/папкам \
    --script ./prepare_receptor.py \
    --out triage_results \
    [--python /полный/путь/к/python]
```

На выходе:
- `triage_summary.csv` — строка на структуру (метод, разрешение, HET-коды,
  bad residues близко/далеко, статус).
- `unknown_het_codes.txt` — все уникальные неизвестные HET-коды с частотой —
  материал для разовой классификации (см. ниже).
- `logs/<имя>.log` — полный вывод по каждой.

**Что делать с неизвестными кодами:** откройте `unknown_het_codes.txt`. Сахара
и буферы можно разом дописать в словарь (`prep_config.py`, набор `BUFFER_CODES`)
или в пользовательский словарь `user_het_dictionary.txt` (формат
`КОД = buffer|cofactor|ion_candidate`). Тогда в полном прогоне их не будут
спрашивать.

### Этап Б — полный прогон (сборка .pdbqt)

```bash
python batch_run.py \
    --root /путь/к/папкам \
    --script ./prepare_receptor.py \
    --out run_results \
    --fallback openbabel \
    [--python /полный/путь/к/python]
```

Флаг `--fallback` управляет поведением при неудаче Meeko:
- `--fallback abort` — **разведочный режим**: проблемные структуры **прерываются**
  и помечаются на ручной разбор. Видно, что Meeko берёт само, а что нет.
- `--fallback openbabel` — **продакшн-режим**: проблемные собираются через
  OpenBabel (обходной путь), получаем `.pdbqt` для максимума структур, каждая
  помечена методом сборки.

Рекомендуемый порядок: сначала `abort` (увидеть картину), потом `openbabel`
(получить результаты).

На выходе:
- `run_summary.csv` — строка на структуру (метод сборки, валидация, статус, путь
  к `.pdbqt`).
- `logs/<имя>.log` + рабочая папка `<имя>/` с промежуточными файлами и сырым
  выводом Meeko (`*_meeko*.txt`) для диагностики.
- В конце — сводка и подсветка структур, требующих внимания (OpenBabel, без
  кофактора, ручная подготовка).

## Проверка качества редокингом

Формальная валидация (Стадия 5) проверяет только **формат** `.pdbqt`. Чтобы
убедиться, что подготовка **не испортила карман**, есть отдельный скрипт: он
докует нативный лиганд (из кристалла) в наш рецептор и считает RMSD к нативной
позе.

```bash
python validate_redock.py \
    --results run_results \
    --root /путь/к/папкам \
    --out redock_results \
    [--targets 2vt4 3kk6 4djh]      # по умолчанию — все
```

- Лиганд готовится через **Meeko** (`mk_prepare_ligand`).
- RMSD считается **без суперпозиции** (in-place) через `rdMolAlign.CalcRMS`:
  рецептор Vina не двигает, поэтому докированная и нативная позы уже в одной
  системе координат. Накладывать их нельзя — это спрятало бы реальное смещение
  позы в кармане.
- Вердикт: **≤ 2 Å — OK** (карман воспроизведён), 2–3 Å — погранично, > 3 Å —
  плохо.

Сводка сравнивает качество **по методам сборки** (Meeko vs OpenBabel) — полезно
убедиться, что обходной путь через OpenBabel не уступает Meeko.

**Нюанс RMSD:** иногда RDKit не может сопоставить нативную и докированную
молекулы (`No sub-structure match`) — обычно из-за рассогласования ароматичности
в `.mol2` от разных источников. Это **сбой расчёта RMSD, а не докинга**: позу
можно проверить глазами в PyMOL. Мы сознательно НЕ «чиним» это костылями, чтобы
не исказить саму метрику.

## Как устроена подготовка

Пайплайн идёт по стадиям. Понимание логики помогает осмысленно отвечать на
вопросы и читать отчёты.

### Стадия 0 — анализ структуры
Читает `.pdb`/`.cif` (через gemmi), определяет метод (X-RAY/CRYO-EM) и
разрешение, берёт первую модель (если несколько). Читает бокс.

### Стадия 1 — очистка и инвентаризация гетероатомов
- **Вся вода удаляется.**
- Каждый HETATM классифицируется по словарям: вода / кофактор / буфер / ион-
  кандидат / неизвестный.
- **Авто-детект лиганда** (`--auto-ligand`): не-словарный HET в боксе с
  наибольшим числом атомов. Если кандидатов несколько — предупреждение.
- Модифицированные остатки (MSE и т.п.) остаются частью белка.
- Раскладывает белок, кофакторы, ионы, лиганд в отдельные `.pdb`.

### His-таутомеризация (между Стадиями 1 и 2)
**Зачем:** Meeko падает, если не может выбрать таутомер гистидина (ничья
HIE/HID/HIP). Поэтому переименовываем `HIS` в конкретный таутомер заранее:
- **Дальние от бокса His** → `HIE` (дефолт, без расчёта — дёшево).
- **Близкие к боксу His** → запускается **PROPKA**: если pKa > 7.4 → `HIP`
  (заряженный, важно для электростатики кармана), иначе → `HIE`.

Логика: для His вне кармана таутомер не важен (лишь бы Meeko не падал); для His
в кармане заряд (HIP) реально влияет на докинг, поэтому считаем PROPKA.

### Стадия 2 — диагностика Meeko на голом белке
Запускает Meeko **без** `-a`, чтобы он отчитался о проблемных остатках (обрезанные
боковые цепи, не матчащиеся шаблонам). Каждый проблемный остаток
классифицируется по расстоянию до **стенки бокса**:
- **близко** (≤ 8 Å) → чинить (формирует карман);
- **далеко** (> 8 Å) → не трогать, уйдёт под `-a` на финале.

### Стадия 2.5 — точечная починка (ТОЛЬКО близкие)
**Это ключевой и самый выстраданный момент.** PDBFixer достраивает недостающие
тяжёлые атомы боковых цепей **только** у близких к боксу остатков. Дальние
**не трогаются вообще**:

- **Дальние НЕ удаляются** физически. Раньше мы их вырезали — но это рвёт
  основную цепь (backbone), и Meeko падает на «padding»-ошибке (повисшая
  пептидная связь). Поэтому дальние остаются на месте (с обрезанными боковыми
  цепями, но целым backbone) и уходят под `-a`, который убирает их **умно** —
  сохраняя backbone.
- **Дальние НЕ достраиваются** PDBFixer'ом. Их кривая достройка по идеальному
  шаблону создаёт клэши → RDKit-ошибка валентности. Поэтому PDBFixer чинит
  строго близкие (фильтр `missingAtoms` по ключу `цепь:номер`).

Целые отсутствующие остатки (петли) по умолчанию НЕ достраиваются (PDBFixer
строит их некачественно). После починки — повторная проверка Meeko.

### Стадия 3 — возврат кофакторов/ионов к боксу
Близкие к боксу кофакторы/ионы можно вернуть в рецептор (с подтверждением, по
умолчанию — нет). Возвращённые добавляются к белку → финальный рецептор.

### Стадия 4 — финальная сборка .pdbqt
Основной путь — Meeko **с `-a`** (выкидывает оставшиеся дальние проблемные
остатки, сохраняя backbone). При неудаче — ветвление по причине (см. ниже),
с возможным переходом на OpenBabel.

### Стадия 5 — валидация формата
Проверяет, что `.pdbqt` непустой, содержит AutoDock-типы атомов, и что
возвращённые кофакторы дожили до финала. **Без редокинга** (он отдельно).

## Классы проблем

Пайплайн различает причины, по которым Meeko не может собрать белок, и
обрабатывает каждую по-своему. Это важно понимать при чтении логов.

### `bad_residues` — обрезанные боковые цепи
Обычная ситуация. Близкие чинятся PDBFixer'ом (Стадия 2.5), дальние уходят под
`-a` на финале (Meeko убирает их, сохраняя backbone). Большинство структур.

### `rdkit_error` — ошибка валентности RDKit
`Explicit valence for atom ... is greater than permitted`. Возникает на
искажённой геометрии (часто крио-ЭМ или низкое разрешение), когда RDKit-санитайзер
Meeko видит «лишнюю» связь. Если возникает **после починки близких** — значит,
достроенная геометрия не принимается RDKit. Решение: собрать **починенный** белок
(с сохранёнными достроенными близкими) через **OpenBabel** — он не делает
RDKit-санитизацию.

### `padding_error` — межостаточная связь (обычно дисульфид)
`Expected N paddings for (A:120, A:204)`. Meeko видит дисульфидный мостик S–S
между остатками, и когда `-a` убирает рядом стоящий проблемный остаток, конец
мостика «повисает». Это **не** RDKit-проблема. На финале Meeko с `-a` чаще всего
справляется сам; если нет — уходит в OpenBabel. (Раньше эту ошибку создавало
наше удаление дальних — теперь мы их не удаляем.)

### `his_ambiguous` — неоднозначность таутомера His
`tied for fewest missing and excess H: HIE HID`. Решается His-таутомеризацией
(см. выше). Если всё же возникает — структура идёт на OpenBabel (`-a` тут не
помогает: Meeko падает на выборе таутомера до стадии `allow_bad_res`).

### Гем / металл-порфирин — особый случай
Гем (HEM) с железом **ломает оба сборщика** — и Meeko, и OpenBabel
(`0 molecules converted`). Если возвращённый кофактор не собирается ничем,
пайплайн собирает рецептор **БЕЗ кофактора** + громкое предупреждение. Для
корректного докинга в гем-карман такую структуру нужно готовить **вручную**
(правильные заряды Fe, координация). Подробнее — [особые случаи](#особые-случаи).

## Как читать результаты

### Методы сборки (`method` в run_summary.csv)
- `meeko` — собрано основным путём (предпочтительно, лучшие типы атомов).
- `meeko_no_cofactor` / `meeko_dropped_cofactor` — собрано Meeko, но кофактор
  был выкинут (он мешал сборке).
- `openbabel` — собрано обходным путём (OpenBabel). Рабочий рецептор, но типы
  атомов грубее, чем у Meeko. Проверьте качество редокингом.
- `openbabel_dropped_cofactor` — собрано OpenBabel **без кофактора**
  (кофактор не переварился, типичный случай — гем).

### Статусы (`status`)
- `done` / `ok` — готово.
- `ok_no_cofactor` — готово, но **без кофактора** (см. предупреждение в логе).
- `aborted` — прервано (в режиме `--fallback abort`); структура требует внимания.
- `manual_needed` — нужна ручная подготовка (обычно гем-белок).
- `error` — сбой запуска (часто — не тот python, см. [PATH](#ловушка-path)).
- `no_input` — в папке нет `.cif`/`box_config`.

### На что обратить внимание
- Структуры, собранные **через OpenBabel** — проверьте редокингом.
- Структуры **без кофактора** — решите, важен ли кофактор; если да — готовьте
  вручную.
- Структуры с пометкой про близкие His и PROPKA — если результат докинга
  странный, проверьте таутомер гистидина в кармане.

## Настройка

Всё крутится в `prep_config.py`:

- `WATER_CODES`, `COFACTOR_CODES`, `BUFFER_CODES`, `CATALYTIC_ION_CANDIDATES`,
  `MODIFIED_RESIDUES` — словари классификации HET-кодов. **Сахара
  гликозилирования** (NAG, BMA, MAN, NDG, FUC...) уже в `BUFFER_CODES` (они
  поверхностные, далеко от кармана). Свободные аминокислоты (GLU/TRP/HIS) и
  редкие лиганд-подобные коды НЕ в словарях — их спрашивают (они неоднозначны).
- `POCKET_PROXIMITY_CUTOFF` (8.0 Å) — порог «близко к боксу» для починки.
- `HETERO_RETURN_CUTOFF` (5.0 Å) — порог для предложения вернуть кофактор.
- `DEFAULT_HIS` (HIE), `HIS_HIP_PKA_CUTOFF` (7.4), `HIS_PROPKA_FOR_POCKET` —
  настройки His-таутомеризации.
- `REBUILD_MISSING_LOOPS` (False) — достраивать ли целые петли (по умолчанию нет).
- `MEEKO_CMD`, `OBABEL_CMD`, `PROPKA_CMD` — имена команд (если у вас другие).

Пользовательский словарь `user_het_dictionary.txt` (формат
`КОД = buffer|cofactor|ion_candidate`) — для разовой классификации без правки
кода; пополняется и из интерактивных ответов («запомнить решение»).

## Особые случаи

### Гем-содержащие белки (P450, пероксидазы, глобины)
Гем ломает автоматическую сборку. Пайплайн соберёт рецептор без гема и пометит
структуру. Если гем критичен для вашего докинга:
1. Подготовьте белок без гема пайплайном (получите `<base>_protein.pdb` или
   `<base>_repaired.pdb`).
2. Отдельно подготовьте гем с правильными зарядами Fe (степень окисления,
   аксиальные лиганды — проксимальный Cys у P450, His у глобинов).
3. Объедините вручную и проверьте в AutoDock Tools.

### Лиганд не найден (`лиганд=?`)
Авто-детект не нашёл не-словарный HET в боксе. Возможные причины: апо-структура
(лиганда нет), лиганд классифицировался как буфер/кофактор, или он не в боксе.
Бокс всё равно задан — подготовка валидна. Если лиганд есть, но «потерялся» —
укажите его явно через `-l КОД` или проверьте словари.

### Сигнальные липиды в кармане (PIP2 и т.п.)
Обычные детергенты/липиды в `BUFFER_CODES` удаляются автоматически. Но
**функциональные** липиды (например, PIP2 в TRPM8) при этом тоже удалятся. Если
работаете со структурой, где липид формирует карман — проверьте вручную и при
необходимости верните его (как кофактор) или уберите код из `BUFFER_CODES`.

### Дисульфиды рядом с карманом (`padding_error`)
Если структура упорно уходит в OpenBabel из-за дисульфида — это ограничение
Meeko, не баг подготовки. OpenBabel-рецептор рабочий; проверьте редокингом.

## Траблшутинг

| Симптом | Причина | Решение |
|---------|---------|---------|
| `ModuleNotFoundError: gemmi` (или meeko) | запущен не тот python | см. [PATH](#ловушка-path); используйте `python`, при котором проходит `check_setup.py`; в batch — флаг `--python` |
| `mk_prepare_receptor.py не найдена` | Meeko не в PATH этого python | активируйте окружение; проверьте `check_setup.py` |
| В batch все структуры `error` / `unrecognized arguments` | устаревшая версия скрипта или не тот python | обновите файлы; проверьте `prepare_receptor.py --help` (должны быть флаги `--non-interactive`, `--auto-ligand`); укажите `--python` |
| Все структуры `unknown` в триаже | пайплайн падает на запуске, ошибка замаскирована | посмотрите `logs/<имя>.log` — там реальная ошибка |
| `0 molecules converted` в OpenBabel | гем/металл-порфирин в рецепторе | пайплайн соберёт без кофактора; для гем-докинга — ручная подготовка |
| PROPKA «н/д» для близких His | PROPKA не дала pKa (мелкий фрагмент/ошибка) | His получит дефолт HIE — это безопасный fallback |
| `vina не найдена` | Vina не установлена | нужна только для `validate_redock.py`; см. [установку](#установка-окружения) |
| RMSD `No sub-structure match` | рассогласование mol2 при чтении RDKit | сбой расчёта RMSD, не докинга; проверьте позу в PyMOL |
